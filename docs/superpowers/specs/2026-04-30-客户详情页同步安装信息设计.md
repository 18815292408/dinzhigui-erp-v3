# 客户详情页同步展示安装信息设计

## 背景

根据「三模块融合单工作线设计」，`/customers/[id]` 是全流程主入口与总览页。当前客户详情页仅在 `in_install`（安装中）和 `completed`（已完结）阶段展示极简的安装状态文本，而 `pending_shipment`（已分配安装师傅后）阶段完全不展示 installation 相关信息。安装反馈记录等关键进程信息必须跳转到 `/installations` 才能查看。

这导致进程监控断裂：销售/店长在客户详情页无法直接看到安装师傅每天反馈的安装进度，必须跨页面查询。

## 目标

将安装管理模块的核心信息（安装状态、预计出货日期、安装反馈记录）同步嵌入客户详情页的对应流程节点，使 `/customers/[id]` 真正成为覆盖全阶段的单页进程监控入口。

**保持安装操作入口独立**：安装状态更新、添加反馈等写操作仍在 `/installations` 完成，客户详情页只做只读展示 + 提供跳转操作入口。

## 当前状态

### 客户详情页 (`/customers/[id]`)
- Server Component 查询 `customers` + `orders` 表，**不查询 installations**
- Client Component 在 `in_install` 区域仅展示：
  - 安装师傅姓名
  - `installation_status` 中文映射（如"已到货""安装中"）
  - "去安装管理查看进度 →" 链接
- `pending_shipment` 区域（已分配安装师傅后）仅展示一段文案，**完全不展示 installation 数据**
- `completed` 区域仅展示完结时间和"订单已完成"文案

### 安装详情页 (`/installations/[id]`)
- 展示完整的安装信息卡片：
  - 关联订单号、预约日期、预计出货日期、当前状态
  - **反馈记录列表**（`installation.feedback` JSONB 数组）
- `InstallationFeedback` 组件负责写操作（确认出货日期、添加反馈、确认完成）

## 设计方案

### 数据获取

在 `app/(dashboard)/customers/[id]/page.tsx` 的 `getCustomer` 函数中，当客户存在订单时，额外通过 `order_id` 查询关联的 installation 记录：

```typescript
// 在获取 orders 之后
let installation = null
if (orders.length > 0) {
  const { data: inst } = await adminSupabase
    .from('installations')
    .select('id, status, scheduled_date, feedback, order_id')
    .eq('order_id', orders[0].id)
    .maybeSingle()
  installation = inst
}
```

将 `installation` 通过 props 传递给 `CustomerDetailClient`。

### 界面展示

#### `pending_shipment` 阶段（已分配安装师傅后）

在现有"已分配安装师傅"文案下方，**新增**以下只读信息：

1. **预计出货日期**：`order.estimated_shipment_date`
2. **安装反馈记录列表**（installation 记录此时可能已创建并产生反馈）：
   - 标题："安装反馈记录"
   - 每条记录以卡片形式展示：内容 + 时间
   - 无记录时显示 "暂无安装反馈"
3. **跳转链接**："去安装管理查看详情 →"（跳转 `/installations`）

#### `in_install` 阶段（订单流程卡片内）

保留现有信息（安装师傅、状态标签、跳转链接），**新增**以下只读信息：

1. **预计出货日期**：`order.estimated_shipment_date`
2. **安装反馈记录列表**：
   - 标题："安装反馈记录"
   - 每条记录以卡片形式展示：内容 + 时间
   - 无记录时显示 "暂无安装反馈"
3. **跳转链接增强**：改为"去安装管理查看详情 →"（跳转 `/installations`）

#### `completed` 阶段（订单流程卡片内）

在现有"订单已完成"文案下方，**新增**安装反馈记录列表（归档查看）。

### 数据结构

`installation.feedback` 为 JSONB 数组，元素格式：
```json
[
  { "content": "string", "date": "ISO8601" }
]
```

### 权限

客户详情页的安装信息为**全角色可见**（只读），与现有订单信息可见范围保持一致。写操作权限仍由 `/installations` 页面控制。

### 组件拆分（可选）

为避免 `customer-detail-client.tsx` 过于庞大，可抽取一个纯展示组件：

`components/installations/installation-info-readonly.tsx`
- Props: `installation: { id, status, scheduled_date, feedback, estimated_shipment_date } | null`
- 负责渲染安装信息只读卡片（状态、日期、反馈列表）

但为减少文件变更量，也可直接内联在 `customer-detail-client.tsx` 的 `in_install` / `completed` 区域中。本方案选择**内联**以保持变更最小化。

## 废弃内容

无

## 影响范围

| 文件 | 变更类型 |
|------|---------|
| `app/(dashboard)/customers/[id]/page.tsx` | 新增 installation 查询 |
