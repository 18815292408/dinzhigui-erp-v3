# 安装后售后流程设计

## 产品定位与目标

在安装流程结束后，增加一个可选的"售后"阶段。安装完成后，用户可以选择：
1. **直接完成订单**（现有流程）
2. **进入售后流程**（新增）

售后阶段主要支持记录售后反馈条目，最终由管理员确认售后完成，订单归档。

## 业务规则

### 状态机

订单状态流转：
```
... → in_install → in_after_sales → completed
              ↘ completed
```

- `in_install` + `installation_status === 'installed'` 时，出现两个按钮：
  - "确认完成订单" → `completed`
  - "进入售后流程" → `in_after_sales`
- `in_after_sales` 时：
  - 可添加售后反馈记录
  - "售后完成" → `completed`
- 回退：
  - `in_after_sales` 可回退到 `in_install`
  - `completed` 不可回退

### 权限矩阵

| 操作 | owner | manager | installer | sales | designer |
|------|-------|---------|-----------|-------|----------|
| 进入售后 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 添加售后反馈 | ✓ | ✓ | ✓(指派) | ✗ | ✗ |
| 售后完成 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 回退到安装 | ✓ | ✓ | ✗ | ✗ | ✗ |

## 数据模型

### installations 表

新增字段：
```sql
after_sales_feedback jsonb DEFAULT '[]'::jsonb
```

结构与 `feedback` 一致：
```typescript
interface AfterSalesEntry {
  content: string
  date: string
}
```

### orders 表

`status` 枚举新增 `in_after_sales`：
```typescript
status: 'pending_dispatch' | 'pending_design' | 'designing' | 'pending_order' | 'pending_payment' | 'pending_shipment' | 'in_install' | 'in_after_sales' | 'completed'
```

## API 设计

### 1. POST /api/orders/[id]/after-sales

进入售后流程。

**请求**：无 body
**权限**：owner / manager
**逻辑**：
- 校验当前 order.status === 'in_install'
- 更新 order.status = 'in_after_sales'
- 更新 order.updated_at

### 2. 修改 POST /api/orders/[id]/complete

支持从 `in_after_sales` 完成订单。

**修改点**：
- 放宽查询条件：也允许 `status = 'in_after_sales'`
- 其余逻辑不变（更新 status=completed, completed_at, archived_at，更新 installations 状态，发送通知等）

### 3. 修改 PUT /api/installations/[id]

支持更新 `after_sales_feedback` 字段。

无需特殊校验，直接透传更新即可。

### 4. 修改 POST /api/orders/[id]/revert

增加 `in_after_sales` 回退逻辑。

**修改点**：
- REVERT_MAP 增加：`in_after_sales: 'in_install'`
- STATUS_LABELS 增加：`in_after_sales: '售后中'`

## 界面设计

### 1. 安装详情页 `/installations/[id]`

在安装反馈卡片（InstallationFeedback 组件）中：

**安装阶段结尾（isInstalled 状态）**：
- 当前：只有一个"确认完成安装"按钮
- 改为：两个按钮并排
  - "确认完成安装"（绿色）
  - "进入售后流程"（蓝色）

**售后阶段（新增 `isAfterSales` 状态）**：
- 展示已有的安装反馈记录（只读）
- 展示"安装已完成"横幅
- 新增"售后反馈记录"模块：
  - 已有记录列表（类似安装反馈样式）
  - 添加售后反馈表单（textarea + 按钮）
  - 售后完成按钮（绿色）

状态判定：
- `isAfterSales` = order.status === 'in_after_sales'
- `isInstalled` = installationStatus === 'installed' && order.status !== 'in_after_sales'

### 2. 客户详情页 `/customers/[id]`

新增 `in_after_sales` 阶段卡片：

```
售后中（安装师傅：xxx）
安装进度：已完成
预计出货日期：xxx

[工厂出货卡片（只读）]

--- 安装反馈记录（只读）---

[去安装管理查看详情 →]

[售后完成按钮]
```

同时修改 `in_install` 阶段：
- 当 `installation_status === 'installed'` 时：
  - 显示两个按钮："确认完成订单" 和 "进入售后流程"

### 3. 订单详情页 `/orders/[id]`

- 增加 `in_after_sales` 状态标签
- 增加售后信息卡片（类似安装信息卡片）
- 当 `status === 'in_after_sales'` 时显示售后完成按钮

### 4. 订单列表 `/orders`

- STATUS_LABELS 增加 `in_after_sales: '售后中'`
- STATUS_COLORS 增加 `in_after_sales: 'bg-purple-100 text-purple-700'`

### 5. 数据看板 `/dashboard`

- `FLOW_CARDS` 增加售后阶段卡片：
  ```

  label: '售后中'
  description: '安装完成，售后跟进中'
  statuses: ['in_after_sales']

- `STAGE_META` 增加：
  ```

  ```
- `order-flow-cards.tsx` 增加图标和颜色：
  - icon: `Wrench` 或 `Headphones`
  - color: `bg-purple-100 text-purple-700`

### 6. 订单流程进度条 `OrderStatusFlow`

增加售后步骤：
```
[{key:'pending_dispatch', label:'待派单'}, ..., {key:'in_install', label:'安装中'}, {key:'in_after_sales', label:'售后中'}, {key:'completed', label:'已完结'}]

### 7. 已完成订单详情页 `/completed-orders/[id]`

增加售后反馈记录展示（如果有的话）。

## 风险评估与回滚方案

**风险**：
- 新增 order status 可能导致现有查询遗漏售后中订单
- 已通过代码审查确保所有 status 枚举使用点均已更新

**回滚**：
- 删除 migration 文件，执行 `supabase db reset`
- 或执行 `ALTER TABLE installations DROP COLUMN after_sales_feedback`
- 回退代码到上一个 commit
