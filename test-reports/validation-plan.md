# 用户权限数据隔离验证方案

## 一、问题分析

### 1.1 当前发现的问题
在之前的测试中，安装人员账号（666）登录后：
- **客户管理页面**：显示"当前阶段暂无跟进中的订单" ✅（数据隔离生效）
- **已完成订单页面**：显示4个已完成订单 ❌（数据隔离可能失效）

### 1.2 根本原因假设
1. **数据库层面**：已完成订单的 `assigned_installer` 字段可能为 NULL，导致 `eq('assigned_installer', user.id)` 过滤失效
2. **数据层面**：这些订单在安装阶段可能没有正确记录 `assigned_installer`
3. **验证方法不当**：仅通过页面截图无法准确判断数据隔离是否生效，需要对比具体数据

## 二、验证目标

### 2.1 核心目标
验证不同角色用户只能访问和操作自己权限范围内的数据

### 2.2 具体验证点
| 验证点 | 期望结果 |
|--------|---------|
| 老板(owner) | 能看到所有组织内数据 |
| 店长(manager) | 能看到所有组织内数据 |
| 销售(sales) | 只能看到自己创建的订单和客户 |
| 设计师(designer) | 只能看到自己被分配的订单 |
| 安装人员(installer) | 只能看到自己被分配安装的订单 |

## 三、验证方法论

### 3.1 数据对比法（主要方法）
1. 记录每个账号在每个页面看到的**具体数据内容**（订单号、客户名等）
2. 对比不同账号看到的数据差异
3. 判断差异是否符合权限规则

### 3.2 API响应验证法
1. 直接调用各页面的API接口
2. 对比不同账号的API返回数据
3. 验证后端权限过滤是否生效

### 3.3 内存快照法（辅助）
1. 使用 Chrome DevTools MCP 捕获内存快照
2. 分析 localStorage、sessionStorage、cookie 变化
3. 验证登出后是否有残留数据

## 六、成功标准

1. **老板/店长**：能看到所有组织内的订单和客户数据
2. **销售**：只能看到自己创建的订单和客户
3. **设计师**：只能看到自己被分配的订单
4. **安装人员**：只能看到自己被分配安装的订单
5. **API层**：无法通过直接访问URL或API获取无权限的数据
6. **内存安全**：登出后无残留数据

## 七、问题处理流程

1. **发现问题**：记录具体现象和数据
2. **定位原因**：分析是前端、后端还是数据库问题
3. **修复问题**：修改对应代码
4. **重新验证**：重复验证步骤确认修复
5. **回归测试**：确保修复不影响其他功能
