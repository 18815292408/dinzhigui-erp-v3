# 用户权限数据隔离验证方案 V2（修正版）

## 一、问题分析

### 1.1 之前方案的逻辑错误
- **错误**：没有先创建测试订单，直接验证数据隔离
- **后果**：页面看不到数据可能是因为没有数据，无法区分是"权限过滤生效"还是"本来就没有数据"
- **修正**：必须先创建属于不同角色的测试订单，再验证隔离

### 1.2 验证前提条件
1. 系统中必须有各角色创建的订单数据
2. 订单必须正确设置 `created_by`、`assigned_designer`、`assigned_installer` 字段
3. 必须有推进中的订单（非已完成状态）才能验证各模块的隔离

## 二、验证目标

验证不同角色用户只能访问和操作自己权限范围内的数据

#### 步骤3：老板账号验证（基准）

#### 步骤6：设计师账号验证
- 登录设计师账号

#### 步骤7：安装人员账号验证
- 登录安装人员账号
- 验证只能看到被分配安装的订单
- 验证看不到未被分配安装的订单

### 阶段三：API层验证

#### 步骤8：越权访问测试
- 使用员工账号尝试直接访问老板订单的详情URL
- 验证是否返回403/404错误
- 调用API获取订单列表，验证返回数据是否符合权限

### 阶段四：内存安全验证

#### 步骤9：登出后数据清理
- 使用Chrome DevTools MCP捕获内存快照
- 验证登出后localStorage、sessionStorage、cookie是否清理
- 验证无残留敏感数据

## 五、成功标准

1. **老板/店长**：能看到所有组织内的订单和客户数据
2. **销售**：只能看到自己创建的订单和客户
3. **设计师**：只能看到自己被分配的订单
4. **安装人员**：只能看到自己被分配安装的订单
5. **API层**：无法通过直接访问URL或API获取无权限的数据
6. **内存安全**：登出后无残留数据

## 六、问题处理流程

1. **发现问题**：记录具体现象和数据
2. **定位原因**：分析是前端、后端还是数据库问题
3. **修复问题**：修改对应代码
4. **重新验证**：重复验证步骤确认修复
5. **回归测试**：确保修复不影响其他功能
